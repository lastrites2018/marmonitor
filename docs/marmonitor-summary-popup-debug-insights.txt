summary popup 디버깅 통찰

문제
- statusline summary badge 클릭 시 popup이 정상적으로 유지되지 않거나, 특정 badge만 동작했다.
- 실제 증상:
  - popup이 잠깐 떴다가 바로 사라짐
  - `⚠`는 동작하는데 `Cl`, `Cx`는 동작하지 않음

핵심 원인

1. `display-popup -E`
- summary popup은 `tmux display-popup -E ...`로 열고 있었다.
- `-E`는 내부 명령이 끝나면 popup을 자동으로 닫는다.
- `marmonitor popup --summary-target ...`는 텍스트를 출력하고 바로 종료하므로,
  popup이 잠깐 보였다가 즉시 사라졌다.

결론
- read-only 결과 popup에는 `-E`를 쓰면 안 된다.

2. tmux `range=user|X` 15바이트 제한
- tmux status line user range의 `X`는 최대 15바이트만 허용된다.
- 기존 summary range 값은 너무 길었다.
  - `summary:agent:claude`
  - `summary:agent:codex`
  - `summary:phase:thinking`
  - `summary:phase:tool`
- 그래서 `Cl`, `Cx`, `🤔`, `🔧`는 실제 mouse range가 깨졌고, helper가 기대한 값을 받지 못했다.
- 반면 `summary:issue`는 15바이트 이하라서 `⚠`만 우연히 동작했다.

결론
- statusline용 mouse range는 사람이 읽는 긴 문자열이 아니라, 짧은 내부 코드로 인코딩해야 한다.
- 현재 사용 코드:
  - `sum:claude`
  - `sum:codex`
  - `sum:gemini`
  - `sum:perm`
  - `sum:think`
  - `sum:tool`
  - `sum:issue`

3. 상태줄 mouse binding 위치
- summary badge는 status line 내 위치에 따라 `Status`, `StatusLeft`, `StatusRight` 이벤트로 들어올 수 있다.
- 이 문제를 의식하지 않으면 특정 badge만 동작하고 나머지는 안 되는 상황이 생길 수 있다.
- 최종적으로는 `MouseDown1Status`, `MouseDown1StatusLeft`, `MouseDown1StatusRight`를 모두 같은 helper로 묶는 구성이 가장 안정적이었다.

결론
- statusline 상호작용은 `Status`만 보면 안 되고, `StatusLeft/StatusRight`도 같이 봐야 한다.

최종 해결
- summary popup에서 `display-popup -E` 제거
- summary range를 짧은 코드로 변경
- helper는 짧은 코드와 기존 legacy range 둘 다 파싱 가능하게 유지
- tmux binding은 `MouseDown1Status*` 계열로 정리

현재 기준 정리
- `Cl`, `Cx`, `Gm`, `⚠`, `🤔`, `🔧` 모두 popup 대상
- `pid:*` 상세 항목은 기존 jump 유지
- read-only popup은 자동으로 닫히지 않음

운영 통찰
- tmux statusline interactivity는 생각보다 제약이 많다.
- 특히 user range 길이 제한은 문서로 남겨두지 않으면 다시 같은 실수를 반복하기 쉽다.
- 앞으로 statusline 클릭 기능을 늘릴 때는:
  1. range 인코딩 길이부터 확인
  2. popup이 결과 표시용인지, interactive shell용인지 먼저 구분
  3. `Status`, `StatusLeft`, `StatusRight` 이벤트 범위를 함께 점검
