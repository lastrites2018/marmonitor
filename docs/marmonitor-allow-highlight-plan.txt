allow 전용 강조 계획

목적
- 일반적인 "증가만 강조"는 정보성 변화까지 눈에 띄게 만들어 집중을 끊을 수 있다.
- 반면 `allow/permission`은 실제 개입이 필요한 상태이므로, 예외적으로 시각 강조를 정당화할 수 있다.
- 따라서 강조는 일반 변화가 아니라 `allow`에만 좁혀서 적용한다.

핵심 판단
- `thinking`, `tool`, `warm`, `done` 증가는 대부분 관찰 정보다.
- `allow/permission`은 사용자가 실제 결정을 내려야 하는 상태다.
- 그래서 interruptive cue는 `allow`에만 허용하고, 나머지는 조용히 둔다.

적용 범위
1. statusline 왼쪽 rail의 permission 항목
2. summary badge의 allow/permission count

적용하지 않는 범위
- `🤔` 증가
- `🔧` 증가
- `warm` 증가
- `done` 증가
- recent-complete 자체의 순간 강조

표현 원칙
- 지속적인 `bold`만 허용
- 배경색 강조 금지
- 깜빡임 금지
- 강한 색상 펄스 금지

왜 bold만 쓰는가
- allow는 빨리 처리해야 하는 상태이므로, 남아 있는 동안 시야에 남아 있어야 한다.
- 하지만 너무 강한 표현은 다른 signal을 모두 잡아먹는다.
- `bold`는 조용하지만 분명한 수준의 강조다.

유지 조건
- permission 상태가 남아 있는 동안 유지
- permission이 해제되면 강조도 자동 해제

구현 방향
- 새로운 전이 TTL이나 count delta 추적은 넣지 않는다.
- 기존 attention/statusline 파생값에서 permission 항목만 `highlighted = true`로 본다.
- summary badge 쪽도 동일 철학을 적용하되, 1차는 detail 항목부터 적용해도 된다.

테스트 기준
1. permission 항목은 시간과 무관하게 강조된다
2. thinking/tool/recent-complete/done 항목은 더 이상 강조되지 않는다
3. allow가 없는 상태에서는 기존 표시와 동일하다
4. hot path benchmark 회귀가 없어야 한다

메타 결론
- 이 계획은 "변화를 더 많이 보이게" 하는 것이 아니라,
  실제 개입이 필요한 상태만 더 분명하게 남기는 방향이다.
- 따라서 인지 부하를 늘리지 않으면서도, 사용자가 놓치면 안 되는 상태만 조용히 앞세우는 방식으로 유지하는 것이 맞다.
