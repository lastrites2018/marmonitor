statusline UX 이후 로드맵

목적
- summary popup과 idle right rail이 구현된 이후, 남은 기능/UX/운영 과제를 실제 상태 기준으로 다시 정렬한다.
- 성능보다 동시 작업 운영 효율, 상태 정보의 의미 정확도, collector 기반 안정성에 초점을 둔다.

실제 코드 기준 상태
- 기준 시점: 2026-04-01
- 1. summary popup MVP: 완료
- 2. summary popup interactive chooser: 완료
- 3. idle right rail MVP: 완료
- 4. `⚠` 의미 복원: 부분 완료
  - `Stalled / Unmatched` 섹션 분리 완료
  - 현재 구현에는 `Risk` placeholder가 남아 있음
  - 이후 문서 기준은 `⚠ = stalled + persistent unmatched`, `transient unmatched` 제외, `Risk` UI 비노출
- 5. attention UX 정제: 부분 완료
  - stale thinking/tool 강등 완료
  - active `•` 표식 제거 완료
  - `recent-complete / warm-idle / cold-idle` projection 정제는 미완
  - 현재 구현은 일부를 recent activity 기반으로 근사하고 있으며, 전이 기준 모델은 아직 미도입
- 6. collector 운영 품질: 부분 완료
  - collector-backed statusline / popup 경로 완료
  - tmux summary click의 collector-only contract 완료
  - manual popup fallback 정책은 유지 중
- 7. popup / dock / watch 역할 정리: 미시작
- 8. 더 큰 아키텍처 확장: 보류

현재 가장 중요한 판단
- popup은 이미 쓸 수 있는 수준까지 왔다.
- idle right rail도 구현되었다.
- 따라서 다음 우선순위는 "새 surface 추가"가 아니라:
  - 왼쪽 attention 영역의 noise를 줄이고
  - `⚠` 의미를 더 정확히 만들고
  - collector 상태를 더 이해 가능하게 만드는 것
  이다.

1. attention noise 축소

상태
- 최우선

왜 지금 이게 먼저인가
- idle right rail이 생기면서 statusline 하단의 역할 분리가 이미 생겼다.
  - 왼쪽: 지금 바로 대응해야 하는 것
  - 오른쪽: 지금 다시 투입 가능한 것
- 이 상태에서 왼쪽이 여전히 오래된 active나 같은 repo 중복으로 noisy하면 전체 UX가 다시 흐려진다.

현재 문제
- `buildAttentionItems()`는 permission / recent thinking만 tier1이다.
- 나머지 alive 세션은 전부 tier2로 들어와 최근 활동 순으로 정렬된다.
- 그 결과:
  - 방금 끝난 세션과 단순 idle 세션이 같은 층으로 보일 수 있다.
  - 1시간 넘은 cold-idle이 statusline 의미를 흐릴 수 있다.
  - 같은 repo의 비슷한 세션이 여러 개 나란히 올라올 수 있다.
  - statusline의 "action-now" 의미가 약해질 수 있다.

핵심 방향
- popup / jump / watch의 전체 attention 후보는 그대로 두고
- statusline에 보여주는 top attention detail만 더 보수적으로 투영한다.
- 특히:
  - `recent-complete`는 왼쪽에 잠깐 유지
  - `warm-idle`은 오른쪽 rail에 유지
  - `cold-idle`은 statusline surface에서 제외
  하는 방향이 맞다.
- 즉 "데이터를 줄이는 것"이 아니라 "statusline surface에만 더 강한 노이즈 필터를 적용"하는 방향이 맞다.
- 이때 가장 중요한 것은 시간 구간보다 전이 기준이다.
  - `recent-complete`는 `thinking/tool -> idle` 전환이 최근에 있었는지로 판단해야 한다.
  - `warm-idle`은 `lastActivityAt`보다 idle 진입 시각 기준이 더 적합하다.
  - collector 재시작이나 snapshot 교체 시 이력이 끊기지 않도록 최소 전이 필드를 공용 상태에 유지해야 한다.

수용 기준
- 왼쪽 상단 detail은 왜 이 항목이 보이는지 설명 가능해야 한다.
- `recent-complete`는 10분까지만 왼쪽에 남아야 한다.
- `warm-idle`은 오른쪽에만 남아야 한다.
- `cold-idle`은 statusline에서 빠져야 한다.
- 같은 repo의 반복 항목은 statusline에서 과도하게 중복되지 않아야 한다.
- popup / jump의 정보 손실은 생기지 않아야 한다.

2. `⚠` 의미 정리

상태
- 다음 우선순위

이미 된 것
- popup 내부 `Stalled`
- popup 내부 `Unmatched`
- `Risk` placeholder 구조

남은 것
- `persistent unmatched` 기준 확정
- `transient unmatched` grace period를 `120초`로 반영
- `Risk`를 UI에서 숨기는 방향으로 정리
- heading / empty-state 표현 정리

수용 기준
- `⚠ n = stalled + persistent unmatched`라고 바로 설명 가능
- popup을 열었을 때 `오래 멈춘 세션`과 `정체 미확인 프로세스`를 구분해 이해 가능
- 잠깐 뜨는 `unmatched` 때문에 `⚠` 숫자가 요동치지 않음

6. popup 데이터 계약 정리

상태
- 보류하되 추적 필요

현재 계약
- tmux summary click:
  - `--collector-only`
  - live scan fallback 없음
- manual `marmonitor popup`:
  - collector 우선
  - collector 없으면 live fallback 가능

남은 질문
- manual popup도 collector-only 기본으로 바꿀지
- 아니면 운영/디버깅 도구로서 fallback을 유지할지

수용 기준
- latency-sensitive 경로와 manual debug 경로의 계약이 문서상/코드상 모두 명확
