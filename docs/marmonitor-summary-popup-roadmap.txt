1. summary popup 1차 MVP

목표
- summary badge를 행동 가능한 UI로 만든다.

상태
- 완료

범위
- clickable badge:
  - `Cl`
  - `Cx`
  - `Gm`
  - `⏳`
  - `🤔`
  - `🔧`
  - `⚠`
- non-clickable 유지:
  - `✅`
  - `AI`
- popup:
  - read-only 또는 very light chooser
- 기존 상세 항목 `pid` 클릭 점프는 그대로 유지

핵심 구현 단위
- `SummaryPopupTarget` 모델
- `selectSummaryPopupItems()`
- `renderSummaryPopup()`
- `marmonitor popup --summary-target <target>`
- tmux click routing 확장

수용 기준
- badge 의미와 popup 결과가 정확히 일치
- 기존 상세 항목 클릭 동작 회귀 없음

2. summary popup 2차 인터랙션

목표
- popup 안에서 바로 jump 가능하게 만든다.

상태
- 진행 중

범위
- 번호 선택 jump
- `q` close
- `Enter` 기본 항목 jump

핵심 구현 단위
- popup chooser 입력 루프
- target client 유지
- jump-back anchor 연동 검토

수용 기준
- popup에서 선택한 항목이 정확한 pane/session으로 이동
- 현재 상세 item direct jump와 충돌 없음

1차 구현 메모
- summary badge 클릭은 interactive popup으로 연다.
- popup 내부에서는:
  - `1-9` 선택 jump
  - `0`은 10번 항목 jump
  - `Enter`는 1번 항목 jump
  - `q` / `Esc`는 종료
- 1차에서는 상위 10개 항목만 직접 선택 대상으로 본다.
- popup chooser는 기존 `jumpToAgentWithAnchor()`를 재사용해서 jump-back anchor semantics를 유지한다.

3. `⚠` 의미 복원

목표
- statusline의 압축된 `⚠`를 popup에서 풀어 보여준다.

범위
- `Stalled`
- `Unmatched`
- future: `Risk`

핵심 구현 단위
- issue filter 분리
- popup section render

수용 기준
- `⚠ n` 숫자와 popup 총합이 일치
- 섹션별 의미가 사용자에게 분명함

4. attention UX 정제

목표
- top list가 더 행동 중심이 되도록 다듬는다.

범위
- 오래된 `active(•)` 축소
- 동일 repo grouping / dedupe
- top N selection 규칙 보정

핵심 구현 단위
- attention ranking 규칙 분리
- grouping 정책 추가

수용 기준
- 상태줄에서 왜 이 항목이 보이는지 설명 가능
- 오래된 noise가 상위로 올라오지 않음

5. collector 운영 품질 강화

목표
- 빠른 것뿐 아니라 안정적으로 동작하게 만든다.

범위
- `stale/degraded` 표시
- auto-restart
- artifact/schema versioning
- config mismatch 진단

핵심 구현 단위
- collector health model 확장
- recovery policy
- diagnostics command

수용 기준
- collector 비정상 시 사용자가 상태를 이해 가능
- stale artifact 문제 재발 방지

6. popup / dock / watch 역할 정리

목표
- 각 surface가 중복되지 않게 한다.

범위
- statusline: 요약
- popup: drill-down / jump
- dock: 지속 모니터
- watch/status: full inspection

수용 기준
- 같은 정보를 여러 surface가 어설프게 중복하지 않음

7. 필요할 때만 최종 구조 확장

목표
- 정말 필요할 때만 더 무거운 구조로 간다.

후보
- full collector
- direct file-read tmux path
- stronger daemon lifecycle

판단 기준
- 현재 UX/운영 개선으로도 부족한가
- 여전히 latency나 stability 이슈가 반복되는가

우선순위
1. popup 내 jump
2. `⚠` 섹션 분리
3. popup의 collector-only 데이터 계약 고정
4. attention dedupe / active 축소
5. collector 운영 품질
6. surface 역할 정리
7. 더 큰 아키텍처 확장

병렬 작업 기준
- 다른 세션에서 바로 구현해도 되는 것:
  - popup 내 jump
  - `⚠` 섹션 분리
  - popup의 collector-only 데이터 계약 고정
- 설계 더 보고 들어가는 게 좋은 것:
  - 4
  - 5
- 실제 사용 데이터 보고 결정할 것:

메타 결론
- summary badge -> popup 자체는 완료되었다.
- 다음 단계의 핵심은 popup을 jump 가능한 chooser로 만들고, `⚠`의 의미를 popup 안에서 복원하며, popup data path를 collector snapshot 중심으로 고정하는 것이다.
- 그 이후는 noise 축소와 collector 운영 품질 개선으로 가는 것이 맞다.
