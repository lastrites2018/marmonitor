summary badge popup 계획 및 현황

목적
- tmux statusline의 summary badge를 클릭했을 때, 해당 badge가 의미하는 세션만 모아서 popup으로 보여준다.
- 기존 상세 attention 항목의 `pid` direct click-to-jump는 유지한다.
- 클릭 해석, 세션 필터링, popup 렌더링, tmux side effect를 분리해서 유지한다.

현재 구현 상태
- summary badge 클릭 -> popup 열기: 완료
- popup 내부 번호 선택 jump: 완료
- popup 페이지 이동(`n`/`p`)과 종료(`q`/`Esc`): 완료
- `⚠` popup의 issue 섹션 정리: 완료
  - 현재 UI는 `Inactive for a While`와 `Unresolved AI Processes` 두 섹션으로 렌더링됨
  - `⚠ = stalled + persistent unmatched`, `transient unmatched` 제외가 반영됨
  - `Risk`는 UI에 노출되지 않음
- tmux statusline click 경로의 popup open: 완료
- 수동 CLI popup의 live fallback 허용: 현재 유지 중

핵심 흐름
- `sum:*` range -> `marmonitor-status-click` -> `tmux display-popup`
- popup 내부 명령:
  - `marmonitor popup --summary-target <target> --interactive`
- 따라서 tmux에서 summary badge를 클릭할 때는 collector 우선 경로를 타되, 필요 시 popup 명령의 live fallback을 사용한다.

popup target 의미

- `agent:codex` -> alive Codex 세션
- `agent:gemini` -> alive Gemini 세션

- `phase:thinking` -> attention 규칙상 유효한 recent thinking
- `phase:tool` -> attention 규칙상 유효한 recent tool
- `issue`
  - 현재 구현: `Stalled + persistent unmatched`
  - popup heading은 `Inactive for a While` / `Unresolved AI Processes`

현재 상호작용
- summary badge 클릭 -> interactive popup chooser open
- popup 내부:
  - `1-9` 선택 jump
  - `0` -> 10번 jump
  - `Enter` -> 1번 jump
  - `n` / `p` -> page 이동
  - `q` / `Esc` -> close
- jump는 기존 `jumpToAgentWithAnchor()` semantics를 재사용한다.

핵심 설계 원칙
- summary badge 의미와 popup 결과는 정확히 일치해야 한다.
- visual style(`plain`, `minimal`, `pill`)와 클릭 의미는 분리한다.
- 기존 `pid` direct jump를 깨지 않는다.
- tmux click 경로에서는 popup 때문에 새 scan을 돌리지 않는다.

데이터 계약

현재 계약
- tmux summary click:
  - collector snapshot 우선
  - collector snapshot이 없거나 읽기 실패하면 popup 명령의 live fallback 허용
- 수동 CLI:
  - 기본은 collector 우선
  - collector가 없으면 `light` live snapshot fallback 가능
  - `--collector-only`를 주면 fallback 금지

이 구분이 중요한 이유
- tmux statusline click은 latency-sensitive 경로다.
- 다만 summary popup은 상태줄 본문 렌더보다 빈도가 훨씬 낮아서, 현재는 실패 대신 fallback을 허용하는 쪽이 실용적이다.
- 반대로 수동 CLI popup은 디버깅/운영 도구 성격이 있으므로, 현재는 fallback 허용이 실용적이다.

현재 남은 범위

1. popup 데이터 계약을 더 명확히 고정
- 남은 판단:
  - tmux summary click도 장기적으로 collector-only로 되돌릴지
  - 아니면 현재처럼 collector 우선 + fallback 허용을 유지할지
  - 수동 `marmonitor popup`은 현재처럼 manual fallback을 유지할지
- 문서/도움말에서 이 차이를 더 명확히 드러낼 필요가 있다.

2. `⚠`의 범주 단순화
- 현재 구현은 이미 `issue = stalled + persistent unmatched` 기준과 `120초` grace period를 반영한다.
- 남은 것은:
  - 사용자-facing 용어와 내부 용어를 더 일관되게 정리하는 일
  - diagnostics surface에서 transient unmatched를 어떻게 보여줄지 결정하는 일

3. popup 내부 grouping / dedupe
- 같은 repo나 같은 종류의 세션이 많을 때, 현재는 flat list다.
- 실제 사용 후 필요성이 확인되면 grouping 또는 dedupe를 붙인다.

4. `✅`, `AI` clickable 여부 재평가
- 지금은 의도적으로 제외했다.
- popup 가치보다 noise가 더 크다고 판단한 상태다.
- 이후 실제 사용 데이터로 재평가할 수 있다.

5. popup 도움말 / discoverability 정리
- 기능은 이미 있지만, 사용자가 summary badge가 clickable인지 알기 어렵다.
- tmux help/banner/doc 문구 보강이 남아 있다.

메타 결론
- summary popup은 더 이상 "계획 단계"가 아니라 "이미 동작하는 기능"이다.
- 지금부터의 계획은 popup을 새로 여는 것이 아니라,
  - collector 우선 + fallback 계약을 어디까지 유지할지,
  - `⚠`를 얼마나 더 단순하고 설명 가능하게 만들지,
  - popup 목록을 얼마나 더 읽기 좋게 다듬을지
  를 정하는 것이다.
