컨텍스트 부하 감소 다음 후보 정리

전제
- 이 문서는 `docs/marmonitor-context-load-reduction-ideas.txt`에서 이미 반영된 항목을 제외하고,
  현재 시점에서 실제로 남아 있는 다음 후보만 다시 정리한 것이다.
- 이미 반영된 항목은 여기서 다루지 않는다.
  - phase 전환 시 짧은 강조
  - origin anchor 세션 표식

남은 후보

1. allow 전용 지속 강조
- 요지
  - 일반적인 증가 강조는 과잉일 수 있으므로 버린다.
  - 대신 `allow/permission`만 남아 있는 동안 조용하지만 분명하게 강조한다.
- 기대 효과
  - 실제 개입이 필요한 항목만 주변 시야에 남겨둘 수 있다.
  - `thinking`, `tool`, `warm`, `done` 같은 정보성 변화는 집중을 끊지 않는다.
- 구현 메모
  - count 증가 비교나 TTL은 필요 없다.
  - permission 항목과 allow badge에만 지속적인 `bold`를 적용하면 충분하다.
- 리스크
  - 배경색, 깜빡임, 강한 색 강조까지 가면 다시 과해질 수 있다.
  - 표현은 `bold` 정도로 제한하는 편이 맞다.

2. popup에서 current/origin 표식
- 요지
  - 기존 popup 항목에 현재 위치와 jump-back origin을 약하게 표시한다.
- 예시
  - 현재 위치 항목: `•`
  - jump-back origin 항목: `↩`
- 기대 효과
  - keyboard/popup jump 상황에서 "내가 지금 어디 있고, 어디로 돌아갈 수 있는가"를 한 번에 볼 수 있다.
  - 새 popup surface 없이 기존 chooser의 맥락 회복 비용을 줄일 수 있다.
- 구현 메모
  - current location과 origin anchor는 둘 다 client 고유 상태다.
  - popup 렌더 마지막 단계에서만 붙이고, 공용 snapshot에는 넣지 않는다.
- 리스크
  - 표식이 너무 강하면 attention 의미와 섞일 수 있다.
  - current/origin이 같은 항목일 때 표기 규칙을 먼저 고정해야 한다.

3. 동일 repo 중복 항목의 시각적 묶음
- 요지
  - 같은 repo가 연속으로 여러 개 뜰 때, 모든 항목을 같은 강도로 읽게 만들지 않는다.
- 기대 효과
  - 상태줄과 popup에서 읽기 비용이 줄어든다.
  - 중복 repo가 많을 때 현재보다 덜 피곤한 surface를 만들 수 있다.
- 구현 메모
  - 첫 항목만 완전 표기하고 뒤 항목은 축약하거나,
    `+N` 집계와 실제 노출 규칙을 더 일관되게 만드는 방향이 가능하다.
- 리스크
  - 어떤 항목을 남기고 얼마나 줄일지 규칙이 어정쩡하면 정보 손실처럼 느껴질 수 있다.

4. keyboard/popup jump에만 제한된 짧은 재진입 브리핑
- 요지
  - 일반 마우스 click jump에는 표시하지 않고,
    keyboard jump / popup selection / ambiguity jump에서만 잠깐 나타나는 짧은 브리핑 prefix
- 기대 효과
  - 빠르게 넘겨보는 jump에서 재진입 비용을 줄일 수 있다.
  - "방금 어디로 들어왔는가"를 잠깐 외부화할 수 있다.
- 구현 메모
  - client-local ephemeral overlay로만 처리한다.
  - 공용 snapshot에는 넣지 않는다.
  - 상세 설계는 `docs/marmonitor-jump-briefing-overlay-plan.txt`에 별도 정리돼 있다.
- 리스크
  - 조건이 너무 넓으면 중복 정보가 되어 오히려 피로를 늘린다.
  - `↩`, origin 표식, idle rail과 충돌하지 않게 엄격히 좁혀야 한다.

5. issue popup 섹션 대비 강화
- 요지
  - `stalled`, `persistent unmatched` 섹션을 더 짧고 더 강하게 보이게 만든다.
- 기대 효과
  - 읽기 전에 문제 종류가 먼저 눈에 들어온다.
  - issue popup의 훑기 속도가 빨라진다.
- 구현 메모
  - 새로운 데이터는 필요 없다.
  - popup 표현 계층만 조정하면 된다.
- 리스크
  - 시각 대비를 너무 세게 주면 다른 popup과 스타일 일관성이 깨질 수 있다.

6. warm-idle의 재투입 적정성 강조
- 요지
  - 오른쪽 rail에서 단순 존재 표시를 넘어서, 지금 다시 쓰기 좋은 항목을 더 약하게 드러낸다.
- 기대 효과
  - 오른쪽 rail이 inventory보다 action hint에 더 가까워진다.
- 구현 메모
  - 새로운 상태를 만들기보다, 이미 있는 warm-idle 정렬 위에서 가장 재투입성이 높은 항목만 약하게 강조하는 쪽이 맞다.
- 리스크
  - "재투입성이 높다"는 기준을 모호하게 잡으면 오히려 의미를 흐릴 수 있다.

7. same-pane no-op jump 피드백 미세조정
- 요지
  - same-pane jump는 이미 no-op으로 처리되고 있으므로, 남은 것은 메시지 톤과 노출 강도를 더 조용하게 다듬는 일이다.
- 기대 효과
  - 기능 자체보다는 사용감이 약간 더 자연스러워질 수 있다.
- 구현 메모
  - 별도 기능이라기보다 UX 미세조정 항목이다.
- 리스크
  - 가치가 작아서 우선순위는 낮다.

우선순위 제안
1. popup에서 current/origin 표식
2. allow 전용 지속 강조
3. 동일 repo 중복 항목의 시각적 묶음
4. keyboard/popup jump에만 제한된 짧은 재진입 브리핑
5. issue popup 섹션 대비 강화
6. warm-idle의 재투입 적정성 강조
7. same-pane no-op jump 피드백 미세조정

우선순위 이유
- `popup에서 current/origin 표식`은 새 surface 없이 바로 맥락 회복에 도움을 줄 수 있다.
- `allow 전용 지속 강조`는 일반 변화 강조보다 과하지 않고, 실제 개입이 필요한 신호만 남긴다.
- `동일 repo 중복 항목의 시각적 묶음`은 정보량을 늘리지 않고 읽기 비용을 줄이는 축이라 가치가 높다.
- `재진입 브리핑`은 잠재 효과가 크지만, 조건을 잘못 잡으면 과해질 수 있어서 앞선 항목보다 뒤에 둔다.

메타 결론
- 현재 남은 후보들의 공통점은 "새 정보를 더하는 것"이 아니라,
  이미 있는 상태를 더 적은 인지 비용으로 전달하는 데 있다.
- 따라서 다음 개선도 새 surface를 늘리기보다,
  현재 statusline / popup / jump 표면의 지각적 품질을 올리는 쪽으로 가는 것이 맞다.
