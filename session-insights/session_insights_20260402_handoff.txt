세션 개요

- 이번 세션의 중심은 `marmonitor`를 더 빠르게 만드는 것보다, "어떤 변경을 유지하고 어떤 변경을 버릴지"를 명확한 기준으로 운영하는 것이었다.
- 실제 축은 다섯 가지였다.
  - statusline / popup / jump-back / idle rail 의미 정리
  - hot path 최적화와 benchmark gate 정착
  - tmux integration diagnostics 추가
  - upstream의 Codex SQLite 아이디어를 benchmark-first로 검증하고 폐기
  - 마지막으로 `현재 marmonitor 세션이 statusline에서 안 보이거나 잘못 보이는 버그`를 재현하고 수정
- 현재 브랜치는 `main`, private remote 기준선도 `main`이다.

명확해진 점

- 이 레포에서 가장 중요한 성능 원칙은 "그럴듯한 최적화"가 아니라 "목표 경로 benchmark가 실제로 좋아질 때만 유지"이다.
- statusline 문제의 본질은 scan 그 자체보다, foreground 경로에서 무엇을 읽고 무엇을 해석하는지의 경계를 지키는 데 있다.
- 상태줄 surface는 의미가 분리되어야 유지된다.
  - 왼쪽 rail: 지금 당장 봐야 할 것
  - 오른쪽 idle rail: 다시 투입 가능한 세션
  - popup / inventory: 상태줄에 다 올리기엔 늦거나 많은 것
- `recent-complete / warm-idle / cold-idle` 구분은 유효하다. 특히 `recent-complete`는 단순 recent activity가 아니라 전이 기반이어야 한다.
- jump-back은 "직전 위치 stack"보다 "첫 jump 전 자리"라는 사용자 개념으로 설명하는 편이 더 맞고, 구현은 client-scoped anchor가 맞다.
- 이번 세션 말미에 분명해진 새 판단:
  - "현재 창 활성화 여부 때문에 안 보이는 것"과 "statusline이 현재 세션을 잘못 투영하는 것"은 다른 문제다.
  - 이번 버그는 전적으로 후자였다.

잘 작동한 접근

- 성능 작업 전에 목표 경로와 benchmark gate를 먼저 정한 것이 유효했다.
  - 이 원칙 덕분에 Codex SQLite처럼 "구조상 그럴듯하지만 실제론 손해인 변경"을 코드에 남기지 않았다.
- hot path 최적화는 공격적으로 가지 않고, thin client 유지 + bootstrap 축소까지만 간 것이 맞았다.
  - `c29655a` fast path bootstrap 축소
  - `698486f` stale collector fast path 테스트 보강
- 공용 파생 모델을 더 명시적으로 묶는 방향은 효과가 있었다.
  - `6aa97cb` 상태줄 realtime derivation 공유
  - `d85541d` summary popup derivation 공유
- popup / click helper는 "얇은 라우터"로 두는 쪽이 맞았다.
  - `eae98a5` summary click precheck를 collector-only로 제한
- UI 변경도 benchmark와 semantics를 같이 보고 유지한 것이 좋았다.
  - `f6dca0c` recent-complete 아이콘 분리
  - `3ede141` warm-idle empty marker 추가
- 마지막 버그는 "runtime 확인 -> 원인 분리 -> 테스트 고정" 순서가 특히 잘 먹혔다.
  - 먼저 실제 statusline 출력과 `status --json`, `debug-phase`를 따로 확인했다.
  - 그 다음 projection 버그와 rollout 매칭 버그를 분리했다.
  - 마지막에 관련 테스트를 현재 계약에 맞게 정리했다.

기대와 다르게 흘러간 지점에서 배운 점

- upstream Codex SQLite discovery는 가져오면 좋아질 것처럼 보였지만, 실제 live benchmark에서는 명확히 나빠졌다.
  - baseline:
    - `status total`: 약 `3680.6ms`
    - `codex.indexCodexSessions`: 약 `1922.5ms`
  - 초기 SQLite 시도:
    - `status total`: 약 `9129.7ms`
    - `codex.indexCodexSessions`: 약 `6946.8ms`
  - 최근 7일 윈도우 보정 후:
    - `status total`: 약 `6826.5ms`
    - `codex.indexCodexSessions`: 약 `5770.7ms`
- 배운 점은 단순하다.
  - SQLite discovery 자체보다, full 경로에서 다시 JSONL을 넓게 읽는 token/phase 보강 비용이 더 컸다.
  - 즉 "발견만 바꾸면 빨라질 것"이라는 기대는 현재 구조에서 성립하지 않았다.
- 작은 helper 미세 최적화도 반복해서 시도했지만, 여러 번 측정해보면 노이즈 수준이거나 오히려 느려지는 경우가 많았다.
  - `status-click` lazy import
  - stale-served foreground lock 제거
  - jump-back anchor alias 캐시
  모두 문서로만 남기고 코드에는 유지하지 않았다.
- 이번 세션 후반의 배움:
  - "no active처럼 보인다"는 현상은 collector 비어 있음이 아니라, statusline projection이 너무 공격적으로 비워져서 생길 수 있다.
  - 또 "현재 세션이 ✓/done으로 보인다"는 현상도 phase parser 자체만의 문제가 아니라, 오래된 rollout에 잘못 매칭된 결과일 수 있다.

현재 구현 상태

- 상태줄
  - thin statusline client 유지
  - collector healthy fast path에서 bootstrap 축소
  - recent-complete / warm-idle / cold-idle 의미 분리
  - idle rail full variant에만 경과시간 표시
  - warm-idle이 0이면 `warm -` 표시
  - 같은 repo의 즉시 항목은 statusline 전용으로 collapse
  - 빈 슬롯은 최근 active로 backfill 하되, 이미 선택된 repo는 다시 붙이지 않음
- jump-back
  - client-scoped anchor
  - `Prefix+g`, `F6`, `↩` click
  - 오른쪽 idle rail 앞에도 `↩` 표시
- popup / click
  - summary popup derivation 공유
  - summary click precheck는 collector-only
- tmux integration
  - `update-integration` 진단 명령 추가
- Codex SQLite
  - 코드에는 남기지 않음
  - 실패 결과와 재시도 제약만 문서화함
- 현재 세션 노출 버그 수정
  - 커밋: `5e84543`
  - 현재 runtime 확인:
    - `2 🤔Cx marmonitor +2 13s`
  - 즉 현재 `marmonitor` 세션은 statusline 왼쪽 rail에 다시 정상적으로 보인다.

이번 버그에서 더 선명해진 이해

- `false empty-state`와 `현재 marmonitor 세션 누락/오분류`는 서로 연결돼 있었지만 동일한 버그는 아니었다.
- 실제 원인은 두 겹이었다.
  1. statusline 왼쪽 rail이 같은 repo의 즉시 항목을 중복으로 먹어서 `marmonitor`가 밀리는 문제
  2. Codex rollout 선택이 오래된 세션에 과하게 고정되는 문제
- 지금은 두 층 모두 수정됐다.
  - statusline projection은 중복 collapse + active backfill + repo 중복 방지로 정리
  - scanner / debug-phase는 실제 process start time을 보고 Codex 세션을 다시 선택
- 재발 방지 문서:
  - `docs/marmonitor-false-empty-statusline-bug.txt`
- 재발 방지 테스트:
  - `tests/utils.test.mjs`
  - 대표적으로
    - 최근 active backfill
    - duplicate immediate collapse
    - done / recent-complete 아이콘 분리
    - Codex session selection heuristics

열린 질문

- `AGENTS.md`와 `docs/marmonitor-performance-architecture-principles.txt`를 repo contract로 커밋할지 여부는 아직 남아 있다.
- idle rail 상호작용은 현재 다른 모델이 별도로 검토 중이다. direct jump와 popup 중 어느 경로를 기본으로 둘지 더 명확히 정해야 한다.
- `recent-complete`는 최소 전이 상태 복원까지는 들어갔지만, 여전히 "완전한 이력"은 아니다. 현재는 false positive를 피하는 보수적 모델을 유지하는 게 맞다.
- `docs/marmonitor-roadmap-opinion.txt`, `docs/marmonitor-summary-popup-roadmap.txt` 등 문서 초안이 워킹트리에 남아 있다. 이걸 남길지 정리할지 판단이 필요하다.

다음 세션 재시작 가이드

- 가장 자연스러운 다음 시작점은 "문서 기준선 정리"다.
  1. `AGENTS.md`
  2. `docs/marmonitor-performance-architecture-principles.txt`
  이 둘을 실제 repo contract로 올릴지 결정한다.
- 그 다음은 "새 최적화"보다 "현재 의미 계약을 문서와 코드에서 더 정렬"하는 쪽이 맞다.
- 성능 작업을 다시 시작한다면 아래 순서를 지킨다.
  1. 목표 경로를 먼저 적는다.
  2. benchmark gate를 적는다.
  3. 개선이 실제로 나오지 않으면 코드는 남기지 않는다.
- statusline/phase 쪽 후속 작업이 필요하면, 먼저 아래를 구분해서 보라.
  1. 원본 snapshot 자체가 잘못됐는가
  2. rollout/session 매칭이 잘못됐는가
  3. statusline projection이 과하게 압축됐는가
  이 셋을 섞으면 다시 원인 파악이 느려진다.

한 줄 결론

- 이번 세션의 가장 큰 성과는 "좋아 보이는 변경은 benchmark로 거르고, 실제 사용자 눈에 보이는 상태줄 버그는 runtime과 projection 경계를 분리해서 푼다"는 기준이 실제로 작동했다는 점이다.
- 덕분에 나쁜 최적화는 코드에 남기지 않았고, 현재 `marmonitor` 세션 누락 문제도 원인별로 정리해서 해결했다.
